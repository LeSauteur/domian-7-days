# DOMIAN 7 DAYS — Visual Restoration Spec

Checkpoint: `a7efc78`  
Scope: визуальный слой поверх готового продукта, без изменения календаря и содержания.

## 1. Цель

Вернуть визуальную ДНК первых концептов: ночной город, глубину, premium mobile-app ощущение, выразительный hero и более сильные состояния. Экран должен оставаться рабочим инструментом руководителя, а не становиться концепт-артом или казино.

## 2. Защищённые слои

Запрещено менять без технической необходимости:

- структуру и тексты этапа A;
- today-first и московскую календарную модель;
- checklist, критерии выполнения и progress;
- ключи и миграцию `localStorage`;
- статусы недели, reset, copy, accordion и навигацию;
- правило редактирования только текущего дня;
- data-driven архитектуру.

## 3. Что восстановить

- Один оригинальный атмосферный media-layer: современный офис ночью, окно и городской свет.
- Четыре визуальных слоя: фон-среда → свет/виньетка → стеклянные карточки → cyan/success акценты.
- Hero как главный кадр дня: крупная типографика, визуальный объект миссии, ясная дата и статус.
- Различимый характер дней через собственный accent tone и вариацию единого orb-артефакта, без семи разрозненных иллюстративных систем.
- Карточки с материальностью: полупрозрачность, внутренний свет, тонкая окантовка и контролируемая тень.
- Более выразительные completed/in-progress состояния без очков, валюты, сундуков и декоративных наград.

## 4. Media-layer

- Фоновый файл не содержит текста, логотипов, людей или UI.
- На desktop видны интерьер и глубина города; на mobile допустим более абстрактный кроп окна и огней.
- Контент всегда лежит на затемняющем слое; контраст текста не зависит от конкретной части изображения.
- Фон фиксирован визуально, но не создаёт горизонтальный скролл и не блокирует взаимодействия.

## 5. Hero

- Приоритет: день → миссия → статус → прогресс → начало действия.
- Hero-object занимает не более трети рабочей ширины на mobile и может быть компактнее на 360 px.
- Заголовок заметно крупнее вторичного текста, но переносится без обрезания.
- Никакого line-clamp для формулировки задачи.
- Календарная полоса остаётся частью первого рабочего блока и не превращается в отдельный экран.

## 6. Above the fold

На ширине 360–390 px без горизонтального скролла пользователь должен увидеть:

- день и дату;
- миссию и текущий статус;
- прогресс;
- недельную полосу;
- заголовок чек-листа и начало первого действия.

Допустимо, что первое действие видно частично, если направление прокрутки очевидно. Нельзя освобождать место уменьшением основного текста ниже читаемого размера.

## 7. Game-app feeling

Достаточный уровень достигнут, когда интерфейс ощущается как ежедневная миссия за счёт иерархии, состояния, прогресса и визуального объекта — без имитации игровой экономики. Используются:

- контрастные state badges;
- световой progress-track;
- заметный completed state;
- разные accent tones дней;
- умеренная реакция карточек на наведение/нажатие.

Не используются: монеты, XP, уровни, лут, персонажи, конфетти, случайные награды и агрессивная анимация.

## 8. Ограничения производительности и доступности

- Один основной растровый фон и один компактный WebP sprite для семи orb-артефактов; остальные элементы — SVG и CSS.
- `prefers-reduced-motion` сохраняется.
- Touch-target не меньше 44 px.
- Видимый keyboard focus для ссылок, checkbox, summary и кнопок.
- Основной текст и элементы управления сохраняют высокий контраст.

## 9. Приёмка

- 360×800, 390×844, 430×932 и desktop 1280×800.
- Нет horizontal overflow, clipping и console errors.
- Первый action начинается в первом viewport на 360×800.
- Все семь дней открываются и визуально различимы.
- Checklist, progress, persistence, reset, copy с фактической вставкой, accordion и навигация работают.
- Старая редакция прогресса продолжает отображаться корректно.
- Скриншоты: минимум текущий день на 360/390, один completed state и desktop.

## 10. Публикация

После визуального прохода и успешного QA: отдельный локальный commit → push текущей feature-ветки → PR → checks → merge → GitHub Pages → production smoke test. Промежуточная версия не публикуется.
